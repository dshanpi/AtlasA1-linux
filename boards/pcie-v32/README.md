# AtlasA1 PCIe candidate for Linux 6.18.63

J58 is a single-lane PCIe slot. The board's J64 selection routes COMBO1 through the U59 switch to either J58 or the JU5 USB3 port. This candidate selects PCIe and restricts link training to Gen1 while validating the board.

The device tree names the PCIe-only resources and reuses the existing SWOUT1 regulator description for PI GPIO power. The schematic connects PI10 to PERST#, PI13 to WAKE# and PI14 to CLKREQ#. This driver controls PERST#. The slot's 3.3 V branch and the Wi-Fi supply share SWOUT2. The driver preserves the PMIC configuration left by board firmware. It programs the Cadence internal-reference configuration and allows up to 200 ms for lock before touching the DWC core. An empty slot can still expose the root port after the DWC link timeout.

CORE page 7 shows RP313 on the PCIe 3.3 V branch and RP235 on the Wi-Fi branch. DB page 19 shows the optional RU73 path to 3.3 V and the R559 path from DCIN-12V to J58. An endpoint requiring 12 V needs the board's DCIN-12V source. Rail voltage and reference-clock amplitude at the connector require measurement on a populated board.

## Rebuild

The kernel-only release recipe accepts `--pcie-v34` for the built-in four-bit PIPE route fix. It verifies the hardware patches and config fragments, builds the kernel package, DTB and matching PowerVR module, and writes their SHA-256 digests.

```sh
bash tools/build_atlasa1_release_kernel.sh /path/to/linux-6.18.63-upstream.tar.gz \
    /path/to/tina /tmp/atlas-v34 --pcie-v34
```

## Reproduce the v32 probe failure

The original v32 probe stopped at the COMBO1 PMA common-ready timeout. To reproduce that measurement, start with the kernel tree generated by the AtlasA1 v30 clean-source recipe. To include the v31 SDIO and Bluetooth transports, apply `atlasa1-wireless-v31.patch` there first and pass its config fragment before `pcie.config` in the merge command below.

```sh
atlas=$PWD
kernel=/tmp/atlas-linux-v30
out=/tmp/atlas-linux-v32-out
mkdir -p "$out"
cd "$kernel"
git apply --check "$atlas/patches/linux/atlasa1-pcie-v32.patch"
git apply "$atlas/patches/linux/atlasa1-pcie-v32.patch"
export ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
scripts/kconfig/merge_config.sh -m -O "$out" .config.atlasa1 \
    "$atlas/boards/pcie-v32/pcie.config"
make O="$out" olddefconfig
make O="$out" -j"$(nproc)" Image allwinner/t736-pcie-v32.dtb modules
```

The new DTB is `arch/arm64/boot/dts/allwinner/t736-pcie-v32.dtb` under the output directory. The published RC1 uses its own DTB. The candidate's kernel release is `6.18.63-t736-hw-v32`. Rebuild PowerVR against this output before a desktop trial.

## Board checks

`sh verify-slot.sh` identifies the root port and any devices below it. `sudo sh verify-slot.sh --rescan` repeats discovery on that root port. With a populated slot, record the downstream PCI ID, negotiated lane width and speed, bound driver and a successful device operation. With an empty slot, record COMBO1 lock from the kernel log, host probing and the result of a scan without a device. Endpoint I/O, PHY signal quality, wake, low-power states and higher link rates require further tests.

## GNOME 合并候选 v43（2026-11-20）

v42 的 GNOME 内核未编入 PCIe/NVMe。用户装入 M.2 PCIe SSD 后，新增 `build_gnome_media_candidate.sh --pcie-nvme`，将已校验的 v34 PCIe、SDIO/UART 补丁与 v42 显示、PRIME 导入和跟踪修复组合，启用 NVMe，保持 400 MHz GPU 和非抢占配置。该选项初始仍以 Gen1 单通道训练；不能把主控编译成功当作 SSD 枚举、读写或高速率验收。

```sh
bash tools/build_gnome_media_candidate.sh /path/to/linux-upstream.tar.gz \
  /path/to/tina /tmp/gnome-pcie-v43 --pcie-nvme
```

板卡 v42 默认启动与匹配的 PowerVR 模块保留，v43 先使用临时启动验证。SSD 的实际识别与 I/O 结果需另附实板记录。
